# AAC 插件 XP 实测

日期：2026-09-22；插件版本：0.1.0。此前 XP 虚拟机启动受阻，本次恢复后补齐以下验证。

## 环境与结论

- Windows XP SP3 x86，5.1.2600，虚拟 CPU 支持 SSE2。
- 当前发行插件 SHA-256：`95e28b7b68db61b07f40612a016fdc25a018239e3b4869914e5fa3ca43b3c5ff`。
- 原版 `TTPlayer.exe` 5.7.9.0 与重建版 XP／Win7 Release 均实际加载新插件并播放问题分片 MP4。
- 本轮未发现需要修改 AAC 插件或播放器源码的 XP 问题；修正的是测试环境与探针初始化，发行 DLL 不变。

测试源码仅在本地 `rebuild/tests/aac_rebuild`；构建、媒体副本及日志保存在 `rebuild/out/test-artifacts/aac_rebuild`。
不上传测试代码，Actions 不运行测试。
最终结果摘要为 `xp-validation-summary.json`，桌面验证日志在 `xp-desktop-final`。
日志回收后已删除来宾中的本次测试目录与临时计划任务，XP 保持运行；原安装目录的插件和设置未修改。

## 原版宿主与重建版实际播放

在 XP 已登录桌面 WinSta0 中，使用独立安装目录、静音设置和播放列表；输入插件仅保留 AAC，
通过进程模块路径确认实际加载的 DLL。观察约四秒后正常关闭，读取播放器保存的进度。

| 宿主／插件 | 文件 | 保存的播放进度 |
| --- | --- | ---: |
| 原版 5.7.9／原插件 | 普通 MP4 | 3,910 ms |
| 原版 5.7.9／原插件 | 原问题分片 MP4 | 0 ms |
| 原版 5.7.9／新插件 | 普通 MP4 | 3,940 ms |
| 原版 5.7.9／新插件 | 原问题分片 MP4 | 3,930 ms |
| 原版 5.7.9／新插件 | 裸 AAC | 3,930 ms |
| 重建版 XP／Win7／新插件 | 原问题分片 MP4 | 3,970 ms |

最终全部用例正常关闭，没有错误对话框或强制结束。原版正常退出码为 1，重建版为 0。
几十毫秒差别来自启动与观察时刻，不用于证明 PCM 是否一致。
这些短时检查不等于原版全曲播放、属性窗口编辑、seek 和转换界面的完整验收。

## 测试环境修正

1. 原插件静态依赖 MSVCR110.dll，XP 测试环境缺少它，导致旧插件对照无法加载。
   只在原插件的两个隔离目录补入 VC++ 2012 x86 运行库，随后普通 MP4 对照正常播放。
   新插件不依赖它；没有将该运行库加入发行包或写入 XP 系统目录。
2. 带 Common Controls v6 清单的测试探针，在 XP 创建配置父窗口前补上 InitCommonControlsEx，
   Nero 配置用例随后通过。此前失败发生在调用插件配置接口之前。
3. 桌面相关验证通过本次专用计划任务在已登录桌面运行，保存子进程输出与退出码。
   重建版使用独立 TTPlayerRebuild.xml 测试设置，避免首次启动提示影响判断。

## 范围限制

CPU 仍需 SSE2；未验证更早 XP Service Pack 或不支持 SSE2 的机器。
分片 MP4 标签／封面仍只读。网络不可定位流、在线 DASH、DRM 和动态 ASC 等分支不在支持范围内。
ADIF、AAC Main／SSR／LD、MP3-in-MP4 及全部损坏输入尚未完成代表性对照。

可以确认当前样本在 XP 中的实际兼容性，不能称为所有原插件行为完全一致。
参见 [实现记录](AAC_PLUGIN_IMPLEMENTATION.md) 和 [原版宿主兼容性](AAC_ORIGINAL_HOST_COMPATIBILITY.md)。
