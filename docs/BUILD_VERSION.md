# DLL 与 Actions 日期构建版本

## 版本规则

DLL 的 `FileVersion`、`ProductVersion` 不再固定为 `0.1.0`，与本次构建的包名、Release 标签一致。
日期采用北京时间，格式与 rebuild 的发行版本相同。

| 构建版本／Windows 字符串版本 | Windows 四段数字版本 |
| --- | --- |
| `2026.09.22` | `2026.9.22.0` |
| `2026.09.22p1` | `2026.9.22.1` |
| `2026.09.22p12` | `2026.9.22.12` |

资源数字字段不能保存 `p` 或前导零，因此分别保存年、月、日、补丁编号。
版本日期必须真实有效；补丁编号为 1～65535，无后缀对应 0。超过范围时构建或分配版本明确失败，避免截断。
这只改变 Windows 版本资源，不改变插件导出接口、宿主 ABI 或解码行为。

## Actions

1. 编译前捕获北京时间日期。
2. 勾选 `Release a Version (GitHub)` 时，读取全部分页标签与 Release，包含草稿占用，按数字递增 `pN`。
3. 将最终版本传给 `build.ps1 -PackageVersion`，生成并编译资源；构建后检查 DLL 的字符串及四段数字版本。
4. 使用同一版本打包、上传 Artifact、生成发布说明并发布。发布阶段仅校验，不再改名或重新分配版本。

发布流程从分配版本到发布完成保持工作流并发锁。外部手动创建的同名 Release 仍会导致发布失败，不覆盖已有内容。
仅构建时使用日期，不读取远程标签，也不发布。Actions 不运行测试。

## 本地与源码包

`./build.ps1 -Package` 在开始时确定日期；加 `-PackageVersion '2026.09.22p1'` 可显式指定。
即使未要求打包，指定版本也会写入 DLL。

直接使用 CMake 时，可通过 `TTP_AAC_BUILD_VERSION` 固定版本。空值表示自动日期：
生成资源的步骤每次构建都会执行，解决同一构建目录跨日使用旧日期的问题；内容不变时不重写资源，避免无谓链接。
`build.ps1` 每次都会刷新 CMake 中的固定版本值。

对应源码 ZIP 根目录内的 `ttp_aac/BUILD_VERSION` 记录本次发行版本。
从源码包重建时，脚本及未指定固定版本的 CMake 都优先采用该值，保证之后重建也保留发行版本。
该文件由打包生成，不提交 Git；显式版本参数可以覆盖它。

运行 ZIP 仍仅包含 `AddIn/ttp_aac.dll` 与 `SHA256SUMS.txt`。
版本资源改变会改变 DLL 与 ZIP 的校验值，历史兼容性记录中的旧版本及旧哈希保留原样。

## 本地验证（2026-09-22）

- 实际构建无后缀版本及 `2026.09.22p2`，读取 DLL 字符串和数字资源确认与参数一致；XP／Win7 导入检查通过。
- 模拟首次发布、同日递增、`p9`／`p10` 数值排序、草稿占用、无效日期、API 失败和资源数值上限，均通过。
- 运行 ZIP 仅含 DLL 与校验文件，内外校验通过；篡改校验清单或源码 ZIP 会拒绝发布准备。
- 解压源码 ZIP 后不指定版本独立构建，保留 `2026.09.22p2`；清除 CMake 固定版本后也能读取源码包记录。
- 同一构建目录修改版本记录后，仅执行 build 即更新 DLL；版本未变时不重写资源或重新链接。
- 工作流通过 actionlint。测试仅在 `rebuild/tests/aac_rebuild` 本地执行；未运行远程 Actions 或发布 Release。
